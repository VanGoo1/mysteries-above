# Храмові будівлі церков (Економіка 6b)

Храми **не генеруються у звичайному світі**. Біля сіл стоять маленькі **шрайни**, і
ПКМ по вівтарю шрайна переносить гравця в кишеньковий світ `mysteries_churches`, де
стоять усі храми зі священиками.

Датапак тут — **лише склад будівель**: два види NBT і жодного `worldgen/`. Куди і скільки
їх ставити, вирішує плагін: рівно одна святиня на село й рівно одна на церкву на весь
світ. Ванільні пули будинків сіл більше не перевизначаються — пул безпам'ятний, і в одне
село могло потрапити до п'яти святинь.

Механізм, конвенція міток і заборони — `.claude/rules/church-structures.md`.

## Встановлення

Датапак **не встановлюється плагіном** — його кладуть руками в `<світ>/datapacks/`
(`/datapack list` має показати `mysteries`). Без нього не буде ні храмів у кишеньковому
світі (плагін напише WARNING на кожну церкву), ні шрайнів у селах.

Ще одне обмеження worldgen: шрайни з'являються лише у **щойно згенерованих** чанках. У
вже обжитому світі біля спавну їх не буде — там святиню ставлять командою
`/church shrine <institutionId>`.

## Файли

| Церква (id у реєстрі)   | Файл структури                | Розмір     |
|-------------------------|-------------------------------|------------|
| church-evernight        | `church_evernight.nbt`        | 35×43×46   |
| church-lord-of-storms   | `church_lord_of_storms.nbt`   | 25×35×39   |
| church-knowledge-wisdom | `church_knowledge_wisdom.nbt` | 23×48×19   |
| church-eternal-sun      | `church_eternal_sun.nbt`      | 31×35×45   |
| church-fool             | `church_fool.nbt`             | 39×51×64   |

Плюс `church_evernight_basement.nbt` (21×4×31) — окремий шматок, який раніше чіплявся
jigsaw'ом під час worldgen. Паста через `Structure#place` ланцюг не розкриває, тож підвал
доведеться ставити другою пастою: offset відносно початку храму = **(+10, −4, +14)**,
порахований із геометрії стикування й не перевірений у грі. Простіша альтернатива —
перезберегти храм разом із підвалом однією структурою.

Решта п'ять церков реєстру (`god-of-combat`, `earth-mother`, `steam-machinery`,
`eternal-darkness`, `ruler-of-calamity`) — у `InstitutionRegistry.SPAWN_DISABLED`, бо
їхні шляхи ще не реалізовані; будівлі їм поки не потрібні.

## Шрайн у селі

`data/mysteries/structure/village_shrine.nbt` — святиня 5×4×5: плита, чотири стовпи з
душевними ліхтарями, п'єдестал і **лодестон-вівтар** у центрі. Один NBT на всі церкви —
кому дістанеться конкретна святиня, вирішує плагін у момент постановки й одразу пише тег
`lotm_church_*` на мітку.

**У NBT немає ні jigsaw, ні мітки** — це чиста будівля. Обидва зайві, бо ставить святиню
плагін (`VillageShrinePlacer`), а не ванільний worldgen: jigsaw був потрібен лише для
стикування з вулицею села і при `Structure#place` лишився б стирчати видимим блоком, а
мітку плагін ставить сам, одразу з потрібним тегом церкви.

Згенерувати заново (наприклад, після зміни розмірів):

```bash
cd tools/nbt
java StructurePatch.java make-shrine ../../mysteries-datapack/data/mysteries/structure/village_shrine.nbt
```

Художню версію можна побудувати в грі й зберегти структурним блоком. Єдина обов'язкова
вимога до неї — **блок-вівтар усередині**, той самий, що в `church.shrine.focus-block`
(типово `LODESTONE`): плагін шукає саме його, щоб знати, куди ставити мітку, і ним же
розпізнає клік гравця. Розмір може бути будь-який — межі захисту рахуються з реальної
геометрії пасти.

Перезбережений шрайн ганяють через `patch --part`, а не `patch`: повний `patch` доводить
мітку до конвенції **священика**.

## Скільки їх у світі

Рівно **одна святиня на церкву на весь світ** і **не більше однієї на село**. Це не
налаштування датапаку, а робота плагіна: він тримає реєстр `shrines.json` і ставить нову
святиню лише тоді, коли генерується чанк із селом, поблизу ще немає іншої святині й
лишились церкви без своєї.

Ванільні пули будинків сіл більше **не перевизначаються** (файли видалено, не
відновлювати). Пул безпам'ятний: кожен конектор вулиці кидає кубик незалежно, тож у одне
село потрапляло до п'яти святинь, якісь церкви не з'являлись зовсім, а будь-який чужий
датапак, що чіпає ті самі п'ять пулів, конфліктував із нашим.

У вже обжитому світі нових чанків немає, тож і святинь не буде — там їх ставлять командою
`/church shrine <institutionId>` (вона теж пише в реєстр, щоб автопостановка не завела
другу святиню тій самій церкві).

## Як додати або перезберегти храм

1. Побудуй храм у світі.
2. Структурний блок у режимі SAVE, назва `mysteries:church_<shortId>` (`shortId` = id
   церкви без префікса `church-`, дефіси → підкреслення), виділи область, SAVE.
3. Скопіюй `.nbt` із `world/generated/mysteries/structures/` у `data/mysteries/structure/`.
4. **Обов'язково** прожени інструмент — сира структура з гри не має тегів на мітці й може
   містити блоки, яких немає на 1.21.1:

   ```bash
   cd tools/nbt
   java StructurePatch.java patch ../../mysteries-datapack/data/mysteries/structure/church_<shortId>.nbt
   ```

Мітку священика можна поставити заздалегідь у грі:

```
/summon minecraft:marker ~ ~ ~ {Tags:["lotm_anchor","lotm_role_priest","lotm_church_<shortId>"],Rotation:[180f,0f]}
```

Якщо мітки немає, інструмент поставить її сам — на підлогу найближче до центру будівлі.
Тег `lotm_box_*` (межі будівлі, з яких живе захист від поламки) інструмент дописує сам і
перераховує при кожному прогоні — руками його не пиши.

## Версія

`pack.mcmeta` оголошує `pack_format: 48` (**1.21.1** — цільова версія проєкту) з
`supported_formats` до 94. Структури, збережені в новішому клієнті, лишаються
придатними: несумісні блоки перейменовує `StructurePatch`. Зворотної міграції в
Minecraft не існує, тож без цього кроку блоки з 1.21.2+ мовчки стають повітрям.
